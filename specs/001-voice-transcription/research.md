# Research — Model Selection

**Status:** decided without a bake-off (PRD §13 decision 12, 2026-10-15).

## Decision

- **Pipeline:** Gemini single-stage. One call takes the audio plus
  `prompts/transcribe-fa.v1.md` and returns structured `{verbatim, formatted}`,
  at $0 on the AI Studio free tier.
- **Model:** `gemini-3.5-flash`, with `gemini-3.5-flash-lite` as the
  fallback. The live probes (§Findings) showed 3.8 too slow and unreliable on
  the free tier, and the lite model far more available under load.
- **Pinning:** the bot reads the exact model ID from `GEMINI_MODEL`, never an
  alias such as `gemini-flash-latest`. An alias can change models under a
  frozen prompt and bypass the golden-transcript gate (Constitution art. V).
- **Temperature:** left at the model's default. Google's Gemini 3 guidance
  advises against lowering it, because doing so can cause looping.

## Why no bake-off

The owner chose to skip a formal pre-build evaluation. Quality is checked on
the live bot instead (AC-002: ≥ 8 of the first 10 real transcripts judged ≥
NotebookLM). If quality falls short, the remedies are cheap: change
`GEMINI_MODEL` (config only) or iterate the prompt (`transcribe-fa.v2.md`).

Accepted risk: a quality problem shows up after the bot is built rather than
before, though the swappable model and pipeline interface keep the cost of a
switch low.

## Findings (T020, 2026-10-15)

Probe: an 8.3 s Persian clip with one English term, generated by
`gemini-3.8-flash-tts`, sent with `prompts/transcribe-fa.v1.md` and the
`{verbatim, formatted}` JSON schema. Free tier; up to 4 attempts with
exponential backoff from 5 s.

| Model | Attempts | Latency of the successful call | JSON | Orthography checks |
|---|---|---|---|---|
| `gemini-3.8-flash` | 503 ×3, then 200 | 173 s | ✓ | all pass |
| `gemini-3.5-flash` | 200 first try | 23 s | ✓ | all pass |
| `gemini-3-flash-preview` | 503 ×4 | — | — | — |

Orthography checks: zero U+064A/U+0643, no ASCII `, ; ?`, `Kubernetes` kept
in Latin script, Persian digits. Both successful outputs were near-identical;
3.5 also placed the ezafe ZWNJ (`درباره‌ی`) correctly.

Second probe, same day, through the Files API path the bot uses (one
attempt per model, same clip):

| Model | Result |
|---|---|
| `gemini-3.5-flash` (inline and file) | 503 |
| `gemini-3.6-flash`, `gemini-3.7-flash`, `gemini-flash-latest` | 503 |
| `gemini-3.5-flash-lite` | 200 in 1.1 s, all orthography checks pass |
| `gemini-2.5-flash` | 404 (not available to this key) |

So the 503s are model capacity, not the request shape, and the Files API
path (upload → `fileData` → delete) works end to end.

Consequences:
- `GEMINI_MODEL=gemini-3.5-flash`, `GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite`.
- Free-tier 503 ("high demand") is common, so FR-028's backoff is essential.
  After the primary model's retries are exhausted on 503/429, the adapter
  tries the fallback model once before failing the job (plan.md §2).
- Most of the latency is model "thinking" (~1,000 thought tokens on an 8 s
  clip). Reducing the thinking budget is a lever if AC-001's 90 s target is
  at risk on long clips.
- One synthetic clip is a smoke test, not a quality evaluation; AC-002 on the
  live bot remains the quality gate.
